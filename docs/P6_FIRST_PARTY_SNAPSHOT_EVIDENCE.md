## Tokenizer projection and exact-byte admission

The pure projection retains every supported source, permission,
transformation, sample, exclusion, purpose, and distribution field. Dataset
rights `approved` maps to tokenizer rights `approved`; dataset safety and
contamination `approved` map to tokenizer `clean`. Dataset transformation tools
map to `<tool-id>@<tool-revision>`, followed by the revision-bound
`admission-projection` transformation.

The resulting tokenizer admission-manifest SHA-256 is
`a2f676b2717e86717d469b9274b91cb3c3bf48daf58e83efe97221e4d5a7151a`.
It is intentionally distinct from the dataset manifest digest.

An isolated verifier imports the tokenizer package only from the pinned local
checkout. With socket creation blocked, it reconstructs the pinned tokenizer
records, checks that their canonical bytes equal the dataset projection bytes,
and admits exactly 1,024 locally regenerated byte strings in manifest order.
The observed result is 1,024 admitted samples, 112,467 bytes, eight sources,
eight tokenizer domains, and exact digest equality with the projected manifest.
The verifier prints only revisions, digests, counts, decisions, and booleans.

The final pull-request head must reproduce this result on unchanged Python
3.11, 3.12, and 3.13 jobs before acceptance. The tokenizer checkout occurs
before verification and is pinned by Git revision; snapshot construction and
admission then run with network socket creation denied.

## Security and repository boundary

- Raw generated bytes exist only in process memory and are not written to Git,
  distributions, caches, logs, reports, CI artifacts, or this evidence.
- Source and corpus data remain untrusted and cannot grant authorization,
  widen classification or target scope, change provider/network policy, relax
  offline operation, extend deadlines or budgets, reduce verification, or
  trigger execution.
- The dataset package retains zero runtime dependencies. It does not import the
  tokenizer package or add a circular repository dependency.
- The isolated evidence harness uses only the exact local tokenizer checkout;
  it performs no acquisition, storage, deserialization, callback, plugin,
  subprocess, provider, remote-AI, or content execution.
- Missing, excluded, duplicate, reordered, changed, rights-ineligible, unsafe,
  cancelled, expired, over-limit, projection-mismatched, or replay-mismatched
  content remains terminal and cannot be promoted or retried under weaker
  controls.
